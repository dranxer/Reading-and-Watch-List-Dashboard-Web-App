# CurioLog Supabase Setup Guide

Follow these steps to set up Supabase as the backend for your CurioLog extension.

## 1. Create Supabase Project

1. Go to [supabase.com](https://supabase.com)
2. Sign in or create an account
3. Click "New Project"
4. Choose your organization
5. Enter project name: `curiolog` (or whatever you prefer)
6. Enter a strong database password and save it securely
7. Select a region close to you
8. Click "Create new project"

## 2. Create the Database Table

1. In your Supabase dashboard, go to the **SQL Editor**
2. Click **"+ New query"**
3. Copy and paste this SQL code:

```sql
-- Create the main table to store curated content
CREATE TABLE public.items (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL,
  title TEXT NOT NULL,
  url TEXT NOT NULL UNIQUE, -- Prevents duplicate entries
  summary TEXT,
  content_type TEXT DEFAULT 'article'::text NOT NULL -- 'article' or 'video'
);

-- Add comments for clarity
COMMENT ON TABLE public.items IS 'Stores the curated articles and videos for users.';

-- Create an index on created_at for faster queries
CREATE INDEX idx_items_created_at ON public.items(created_at DESC);

-- Create an index on content_type for filtering
CREATE INDEX idx_items_content_type ON public.items(content_type);
```

4. Click **"Run"** to execute the SQL

## 3. Set Up Row Level Security (RLS)

1. Go to **Authentication → Policies**
2. Find your `items` table and click **"Enable RLS"**
3. Create a policy for public read access:
   - Click **"New Policy"**
   - Select **"Create a new policy from scratch"**
   - Policy name: `Allow public read access`
   - Allowed operation: `SELECT`
   - Target roles: `anon, authenticated`
   - USING expression: `true`
   - Click **"Review"** and **"Save policy"**

Note: For this portfolio project, we'll use the service_role key for writing, which bypasses RLS. This is secure as long as you don't expose the key publicly.

## 4. Get Your API Keys

1. Go to **Project Settings → API**
2. Copy these values:
   - **Project URL** (e.g., `https://your-project.supabase.co`)
   - **anon public** key (for the website)
   - **service_role secret** key (for the extension)

⚠️ **Important**: Never expose your service_role key in client-side code or commit it to version control.

## 5. Configure the Extension

1. Load your CurioLog extension in Chrome
2. Click the extension icon
3. Enter your Supabase URL and Service Key in the configuration section
4. Click "Save Configuration"

## 6. Test the Setup

1. Visit an article page (like a Medium post or Wikipedia article)
2. Wait 30 seconds for auto-detection, or click "Test Current Page" in the extension popup
3. Check your Supabase dashboard → Table Editor → items to see if the content was saved

## Environment Variables for Website

Create a `.env.local` file in your website directory:

```
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here
```

## Troubleshooting

### Extension not saving content?
- Check the browser console (F12) for error messages
- Verify your Supabase URL and service key are correct
- Make sure the `items` table exists in your database

### Website not loading content?
- Check your `.env.local` file has the correct values
- Verify you're using the `anon` key (not service_role) for the website
- Check that RLS is enabled with the public read policy

### CORS issues?
- Supabase should handle CORS automatically
- If you see CORS errors, check your project settings

That's it! Your CurioLog should now be saving articles to Supabase automatically.
